ABSTRACT

Efficient transit intelligence and transparent real-time tracking are critical pillars of modern passenger transportation. The Indian Railway network—spanning over 68,000 route kilometers and serving upwards of 23 million passengers daily—presents one of the most complex operational landscapes in the world. Conventional passenger railway applications suffer from fragmented interfaces, lack of spatial route visualization, poor resilience against upstream API rate limiting, and zero visibility into geographical terrain or atmospheric micro-climates along the journey corridor.

This Industrial Training Report presents the comprehensive architecture, design, and implementation of RailGaadi (Train Tracker), a state-of-the-art, client-side real-time GIS passenger tracking and journey intelligence platform. Built entirely using modern ES modules, vanilla CSS custom properties, and MapLibre GL WebGL cartography without runtime framework bloat, the application was engineered in two systematic, production-grade development phases.

Phase 1 (Core Tracking Foundation) established the reactive Pub-Sub state machine (store.js), resilient integration with the RailRadar API via an authenticated local reverse proxy, high-performance vector polyline route rendering, spatial mathematical calculations (Haversine formula, Great Circle bearings, and piecewise polyline interpolation via geoService.js), live OpenWeatherMap integration at exact geographic coordinates, and Shuttle Radar Topography Mission (SRTM) elevation profiling via OpenTopography.

Phase 2 (Advanced Transit Intelligence & PWA) substantially elevated the platform by incorporating an interactive Station Live Departure & Arrival Board simulating digital station displays, a complete Dark Mode Design System, an animated Slide-in Favourites and Recent Searches Drawer with local storage persistence, an HTML5 double-buffered Real-Time Speed Telemetry & Velocity Profile Canvas, native Browser Push Notifications for operational delays exceeding 15 minutes, and a Progressive Web Application (PWA) Service Worker (sw.js) providing offline application shell caching and resilient failover.

Chapter 1

Introduction

1.1 Project Overview

Railway networks represent the economic and social lifeline of populous nations. In India, the railway infrastructure coordinates over 13,000 passenger trains daily, connecting remote rural terminals to densely populated metropolitan centers. For millions of daily commuters, tourists, and business travelers, access to timely, precise, and contextual journey data is an operational necessity.

The project titled "TRAIN TRACKER (RAILGAADI)" is an advanced web-based spatial application engineered to deliver rich, real-time journey situational awareness. Unlike conventional timetable queries that display dry, tabular lists of static timings, RailGaadi combines live GPS telemetry, interactive WebGL cartography, digital elevation data, micro-climate forecasts, and electronic station board intelligence into a unified, responsive single-page web architecture.

1.2 Problem Statement

  • Information Fragmentation: Passengers switch between separate portals for train tracking, platform info, and weather conditions.
  • Lack of Spatial Route Visibility: Tabular checklist formats fail to represent physical geography, terrain ascents, or curves.
  • API Quota Lockouts: Strict third-party rate limits crash naive applications when thresholds are exceeded.
  • Framework Bloat: Heavy single-page frameworks introduce massive megabyte bundles, lagging on transit 3G/4G networks.
  • Network Dropouts in Transit: Lack of offline service worker caching creates blank screens inside railway tunnels.

Chapter 6

Implementation & Code Architecture

6.3 Spatial Math & Polyline Interpolation (geoService.js)

To calculate geographic distances, train headings, and smooth vehicle positioning along polyline segments, GeoService implements spherical trigonometry algorithms directly in JavaScript:

// js/services/geoService.js - Spherical Spatial Mathematics
export class GeoService {
  // Haversine Great-Circle Distance (Kilometers)
  static haversineKm(lat1, lon1, lat2, lon2) {
    const R = 6371; // Earth radius in km
    const dLat = ((lat2 - lat1) * Math.PI) / 180;
    const dLon = ((lon2 - lon1) * Math.PI) / 180;
    const a = Math.sin(dLat/2)**2 + 
              Math.cos((lat1*Math.PI)/180) * Math.cos((lat2*Math.PI)/180) * Math.sin(dLon/2)**2;
    return R * 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
  }

  // Initial Compass Bearing Angle (Degrees: 0 - 360°)
  static initialBearing(lat1, lon1, lat2, lon2) {
    const φ1 = (lat1 * Math.PI) / 180, φ2 = (lat2 * Math.PI) / 180;
    const Δλ = ((lon2 - lon1) * Math.PI) / 180;
    const y = Math.sin(Δλ) * Math.cos(φ2);
    const x = Math.cos(φ1)*Math.sin(φ2) - Math.sin(φ1)*Math.cos(φ2)*Math.cos(Δλ);
    return (Math.atan2(y, x) * 180 / Math.PI + 360) % 360;
  }
}
